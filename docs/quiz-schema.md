# Контракт данных квиза

Этот файл — граница между контентом и приложением. Приложение не должно знать ничего о конкретных вопросах, только о схеме.

## Структура репозитория

```
/data
  rn-architecture.json
  rn-performance.json
  js-core.json          # позже
  ...
  topics.json           # реестр тем
/docs                   # исходные md-файлы, из которых генерируются вопросы
/src                    # приложение
```

## Формат файла темы

```json
{
  "topic": "rn-architecture",
  "title": "React Native: архитектура",
  "version": 1,
  "questions": [ ... ]
}
```

## Схема вопроса

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | да | Уникален глобально. Формат `<topic-slug>-NNN`. **Не переиспользовать** после удаления вопроса — прогресс пользователя привязан к id |
| `topic` | string | да | Совпадает с `topic` файла |
| `type` | enum | да | `single` \| `multi` \| `code-output` \| `open` |
| `question` | string | да | Markdown. Может содержать блок кода |
| `options` | string[] | для single/multi/code-output | Markdown-строки |
| `correct` | number[] | для single/multi/code-output | Индексы правильных вариантов. Для `single` ровно один элемент |
| `explanation` | string | да | Markdown. **Главное поле** — именно оно работает как карточка при повторении |
| `followUp` | string[] | нет | «Куда копнут дальше» — показывать после ответа |
| `difficulty` | 1\|2\|3 | да | 1 — база, 2 — уверенный уровень, 3 — сеньорный |

### Про `type: "open"`

Вопрос без вариантов — пользователь отвечает себе вслух, потом открывает `explanation` и сам оценивает: «знал / частично / не знал». Самооценка идёт в тот же прогресс, что и обычные вопросы. Это самый полезный тип для подготовки к собеседованию, поэтому режим «показать ответ» должен быть в один тап.

## Прогресс

Хранится отдельно от контента, ключ — `id` вопроса:

```json
{
  "rn-arch-004": {
    "seen": 3,
    "correct": 2,
    "lastAnswer": "2026-09-13T10:00:00Z",
    "box": 2
  }
}
```

`box` — номер интервала для повторения (схема Лейтнера). Простая рабочая реализация: 5 коробок, правильный ответ повышает на одну, неправильный сбрасывает в первую. Интервалы: 0 / 1 / 3 / 7 / 21 день.

Хранилище: `Telegram.WebApp.CloudStorage` с фолбэком на `localStorage`. CloudStorage хранит строки до 4096 байт на ключ — прогресс на несколько сотен вопросов надо либо разбивать по темам, либо ужимать (короткие ключи, массив вместо объекта).

## Режимы приложения

1. **Квиз** — вопросы темы подряд, результат в конце
2. **Повторение** — только то, что пора повторить по `box`, вперемешку из всех тем
3. **Работа над ошибками** — где `correct / seen` ниже порога

## Правила добавления контента

- Новый вопрос — только добавление в массив, без изменения существующих `id`
- Изменил смысл вопроса — новый `id`, старый удалить
- `version` файла повышать при любом изменении, приложение может показывать это в отладке
- Валидация: `correct` не выходит за границы `options`, `id` уникальны — имеет смысл проверять в CI
